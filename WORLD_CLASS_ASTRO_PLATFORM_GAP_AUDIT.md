**Scope:** repository contents at audit time; this is a status comparison, not an implementation authorization.

## How to read the statuses

- **Implemented (baseline):** relevant code and/or screens exist. This does not mean every scenario is production-certified.
- **Partial:** a subset or foundation exists, but the document's full workflow, platform support, governance, or validation is missing.
- **Not found:** no corresponding implementation was located in the current project modules. A requirement in the specification or roadmap alone does not count as implementation.
- **Unverified:** implementation may exist, but the reviewed reports do not provide the evidence needed to claim acceptance.

## Priority work list

### P0 — Product and release gates

1. **Ephemeris licensing and Calculation Contract v1.** Document chosen ephemeris, redistribution rights, precision, conventions, supported date/location bounds and known unsupported cases before commercial SDK release.
2. **Platform truth.** Decide whether iOS is in the immediate delivery scope; the current checkout has Android and Desktop targets but no iOS target/Xcode project. Define the public Android/Desktop/iOS artifact and version policy.
3. **Parity and regression lab.** Add a shared cross-platform harness and source-backed chart, timezone, Panchang, Dasha, Varga and rule vectors. Track known JKR disagreements as ambiguous/unsupported rather than silently passing.
4. **Phase 10.12A device acceptance.** Complete domain-specific inference, offline/privacy, load lifecycle, concurrency, fallback, diagnostics and Interaction Sentinel scenarios on supported device classes.
5. **Privacy/consent model.** Specify local encryption, data lifecycle, family/home/image consent, export/delete, optional sync and analytics boundaries before adding family graph or visual scanning.

### P1 — User-facing features explicitly in the master specification

6. **Calendar and global data:** timezone-aware current location, regional Panchang/holiday packs, source governance and signed offline updates.
7. **Personal context and family:** goals/context persistence, graph provenance, verified consented relationships, spouse insights and smart calendar.
8. **Timing workflows:** matching, Muhurta, Prashna and transparent date-window ranking.
9. **Vision backlog:** certificate OCR and measurement workflows; Vastu only after an accuracy/safety plan; palmistry dataset validation.
10. **Guidance completion:** daily plan, mantra/practice content, proactive questions, notification scheduling and wallpaper preview/export.

### P2 — Commercial and distribution plane

11. **Admin Panel/backend:** private operational control plane for customer/company, plans, packs, content, flags, releases and audit.
12. **Billing and signed entitlements:** store integration, server signature, capability enforcement, offline cache/grace policy and pricing-change governance.
13. **SDK productization:** AAR, XCFramework and Desktop artifacts, examples, API docs, license/support policy and compatibility validation.

## Important roadmap correction

The repository's `docs/CORE_FEATURE_ROADMAP.md` is explicitly versioned 1.1 / Phase 8.1 and labels Numerology and Gemstone as `FOUNDATION_ONLY`, and the AI runtime as `PARTIALLY_IMPLEMENTED`. Those labels are stale relative to the current source and later Phase 10.12 reports: Numerology has substantial engines/UI/tests; Gemstone has recommendation/inventory/UI plus the recent image sync; and native AI has been exercised on a device. At the same time, the later AI report still marks broad acceptance incomplete. Update the roadmap to distinguish implementation maturity from acceptance evidence and align phase numbers with sections 40 and 49 of the supplied specification.
