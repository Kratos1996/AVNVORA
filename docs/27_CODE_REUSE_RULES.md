# AYNVORA Code Reuse Rules
Version: 1.0

## Search Before Create
Before creating a class/function/component:
- search the repository
- identify existing equivalents
- evaluate whether extension is possible

## Reuse Hierarchy
1. Existing approved component/function
2. Existing abstraction extended safely
3. Shared module utility
4. New reusable abstraction
5. One-off implementation only with documented justification

## Prohibited
Duplicate validation, duplicate astrology rules, duplicate networking, duplicate storage wrappers, duplicate UI components and platform-specific copies of common domain logic.
